# v0.3 Tier 3 — novice-facing polish (execution notes)

The final tier of [v0.3-roadmap.md](v0.3-roadmap.md): three self-contained polish
items. What actually shipped, and why:

## 1. Per-member comment rate limiting — already done

Found already implemented and at parity: `handlePostComment` / the channel message
handler gate on `RateLimitAllow("comment:"+user.id, …)` (Go) and
`rateLimitAllow(… "comment:"+auth.user.id …)` (edge), both 20 / 5 min. The roadmap
deferral was stale — no work needed beyond confirming the constants match.

## 2. `<friendo-map>` — Leaflet map component

`<friendo-map target-type target-id>` renders a target's geo-tags (the locations
API) as an **interactive Leaflet map** (open-source, BSD-2) with OpenStreetMap tiles
(free, no key) — a circle marker per location, label in a popup. Leaflet is
**lazy-loaded from a CDN only on pages that use a map**, so the rest of the SDK stays
dependency-free. Public read (no sign-in). Styleable via `::part(map)`.

## 3. Persona switcher — per-user default persona

Chosen model: a member marks one of their author profiles (personas) as **default**;
all their comments/messages/reactions attribute to it. The default is a pointer,
`users.default_author_id` (migration `0010`, both runtimes) — a single row to update,
no "unset the others" bookkeeping.

- **Data layer** (both runtimes): `DefaultAuthorID` now honors the pointer (falling
  back to the earliest profile), so *no write-path changes* were needed — every
  existing attribution call already routes through it. Added `ListPersonas`,
  `CreatePersona`, `SetDefaultPersona` (+ `authorBelongsTo`).
- **API** (both runtimes, member-gated): `GET/POST /_/api/me/personas`,
  `POST /_/api/me/personas/:id/default`.
- **SDK**: `<friendo-auth>` gained a "Posting as … · personas" switcher — list
  personas (default marked), pick one, or add a new one inline.

## Verification

- REST parity: `scenarios.json` +7 persona steps → **162 steps** on both runtimes;
  migration `0010` applies cleanly on the fresh edge D1.
- Browser (Playwright, now a dev dependency + `npm run test:sdk`): a self-contained
  harness boots the Go runtime and drives Chromium to confirm `<friendo-map>` paints
  its markers and the `<friendo-auth>` switcher lists/creates/switches personas
  (asserting the change persists server-side). See
  [tests/sdk-map.mjs](../tests/sdk-map.mjs), [tests/sdk-persona.mjs](../tests/sdk-persona.mjs).

## Out of scope (noted)

- Per-action persona choice (switch per comment) — deliberately not taken; the
  per-user default is the simpler, novice-friendly model.
- Admin-SPA persona management — the member-facing SDK switcher covers the community
  use; an admin surface can follow if authoring-as-persona needs it.
