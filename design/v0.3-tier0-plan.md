# v0.3 Tier 0 — server-side community content (execution plan)

> **Historical / superseded.** Pre-pivot execution plan. The features shipped, but the
> "both runtimes / parity" framing is obsolete — friendo has unified on a single **Go
> runtime**. See [network-accounts.md](network-accounts.md) and the repo `ROADMAP.md`.

Sequenced plan for the first tier of [v0.3-roadmap.md](v0.3-roadmap.md): make a
post's **approved comments, reaction tallies, and poll** renderable directly in a
template on both runtimes, so a novice can show community data without shipping JS.

**Design principle carried in:** intuitive markup, not parity dogma. Comments,
reactions, and polls are *content* that earns a server-side read (SEO, no-JS). The
template form (`{{ record.comments }}`) and the SDK component (`<friendo-comments>`)
are two spellings of the same data. (Realtime chat + maps stay client-side — not in
this tier.)

## Context (verified in code)

- The single-post template variable is **`record`** (a `map[string]any` in Go / a
  decoded object on the edge), attached as `ctx.record` only on dynamic single-record
  pages — Go: [server.go:409](../runtime/go/server/server.go#L409); edge:
  [index.js:1909](../runtime/edge/index.js#L1909).
- The public data helpers already exist and are behavior-matched across runtimes:
  - Comments — `ListCommentsByPost(id, false)` / `COMMENT_SELECT` + `status='approved'`.
  - Reactions — `ReactionCounts("post", id, "")` / the reactions `GROUP BY emoji` query.
  - Poll — `ResolvePollBySlug(slug)` + `GetPoll(id, "")` / `resolvePollBySlug` +
    `pollWithTallies(env, siteId, id, "")`. Both lazily create the poll from the
    declaring post's front matter on first view (a matched side effect).
- Both runtimes decode the `data` JSON column into a nested map, so
  `record.data.poll.slug` already resolves.

## The contract (identical shape both runtimes)

Enrich the focused `record` (only) with three keys. Absent poll → key omitted, so
`{% if record.poll %}` is falsy. Comments/reactions are always present (possibly
empty lists).

| Key | Value |
|---|---|
| `record.comments` | list of approved comments, oldest first: `{id, post_id, parent_id, author_id, author_name, author_avatar, body, status, created}` |
| `record.reactions` | list `{emoji, count, reacted}` (`reacted` is always false — no server-side viewer), ordered by emoji |
| `record.poll` | present only if the post declares `data.poll.slug`: `{id, slug, question, options:[{index,text,votes}], total_votes, closes_at, my_vote:null}` |

`reacted`/`my_vote` are viewer-relative and have no meaning in a public server
render, so they take their "no viewer" values (mirrors passing `authorID=""` to the
existing helpers) — the SDK component still owns the interactive, viewer-aware view.

## Steps

1. **Go — `attachCommunityRelations(db, record)`** in `runtime/go/server/server.go`,
   called right after `ctx["record"] = record`. Reuses the three helpers above;
   pulls the poll slug from `record["data"].(map[string]any)["poll"]`.
2. **Edge — `attachCommunityRelations(env, siteId, record)`** in
   `runtime/edge/index.js`, called right after `ctx.record = record`. Byte-mirrors
   the Go SQL/shape (same `COMMENT_SELECT`, same reactions query with an empty
   viewer bind, same `resolvePollBySlug`/`pollWithTallies`).
3. **Demonstrate** in `testsite/pages/blog/[slug].html` — render the approved
   comments and reaction tallies server-side alongside the existing `<friendo-*>`
   components, so the two spellings sit side by side and the path is exercised.
4. **Verify** — `go build`/`go vet`, `node --check` the edge bundle, and render the
   same seeded post on both runtimes and diff the community section.

## Out of scope (later tiers)

- The **render-layer parity suite** that makes this diff a standing CI check is
  **Tier 2** — this tier verifies by hand-driven render + diff.
- **Galleries** (`{{ record.gallery }}`) are **Tier 1**.
- Nested/threaded comment *rendering* helpers, pagination — post-1.0 nicety; the raw
  `parent_id` is exposed so a template can nest if it wants.
