# friendo v0.4 — roadmap

> **Status: planned.** Scoped 2026-08-17, immediately after the v0.3.0 tag. Builds on
> the shipped single-runtime pivot + network mode — see the repo
> [ROADMAP.md](../ROADMAP.md) and [network-accounts.md](network-accounts.md).

**Scope theme: make the network safe to open to real tenants.**

v0.3 was the consolidation release — it made the *site* surface solid (intuitive
markup for every feature, coverage past REST). v0.4 turns to the *network*: friendo.world
is live on network mode, but it is still an operator-shaped demo. Everything that keeps a
public sign-up list from costing the operator money or a support headache is missing:
there is no cap on what an account can create, account management stops at the console UI,
and a tenant cannot bring their own domain.

The desktop editor (Phase 2) stays deferred. It is the bigger novice-facing bet and an
independent track; opening the network is the thing blocking real users *today*.

## Where network mode actually stands

Grounding for the work below, from the code as of v0.3.0:

| Piece | Today |
|---|---|
| Site registry | folder-based — [`Registry`](../runtime/go/network/registry.go) walks the network root; a `Site` is `{Subdomain, Dir, Name}` |
| Ownership | `site_owners (subdomain PK, account_id)` in the accounts DB ([account.go](../runtime/go/network/account.go)) |
| Network config | `network_settings` key/value; **`signups`** (`open`/`invite`, default invite) is the only key |
| Routing | [`Dispatcher.subdomain`](../runtime/go/network/dispatcher.go) strips `.<baseDomain>` from the request host — the **only** host→site mapping |
| Auth | passwordless OTP + device-auth; `operator` is a capability on an account |
| Limits | **none** — any account can claim unlimited subdomains |

## Tier A — Quotas (no account can cost you unbounded money)

The smallest change that makes `signups = open` a survivable setting. Per the
network-accounts open items, first cut is a **site-count cap**; storage follows.

- **Default cap** as a `network_settings` key (`quota.sites_per_account`), operator-editable
  from the console + CLI, so there is no recompile to change it.
- **Per-account override** — an `account_quotas (account_id, sites)` row wins over the
  default, so the operator can lift the cap for one tenant without lifting it globally.
  Accounts holding `operator` are exempt.
- **Enforced at the claim path** — the self-service `POST /api/account/sites` counts
  `site_owners` for the account and refuses past the cap with a **clear, actionable 403**
  (not a bare error — the message is the only thing a novice sees).
- **Surfaced before the wall** — the console shows *used / allowed*, and `friendo deploy`
  prints the same when it fails, so hitting the cap is never a surprise.
- **Storage quota** is scoped but *decided, not built* here — accounting is not obvious once
  media lives in R2 rather than on the box. Decide whether it is measured (a periodic
  per-site walk) or metered (tracked at upload) before committing; the count cap ships first
  either way.

## Tier B — Accounts & signups management past the console UI

Today the operator can toggle signups and mint invites in the console, and grant operator
from the CLI. The gaps are the ones that show up the first time something goes wrong.

- **`friendo network accounts`** — list accounts with their site counts and capabilities;
  the CLI counterpart to what the console shows.
- **Suspension** — suspend an account (blocks new sessions + new claims) and suspend a site
  (dispatcher serves a hold page instead of the tenant). This is the abuse lever that has
  no answer today short of `network destroy`, which is irreversible.
- **Session revocation** — drop an account's `account_sessions` rows, for the "I lost my
  laptop" case that passwordless auth otherwise has no answer to.
- **Invite lifecycle** — list, revoke, and expire invites, not just mint them.

## Tier C — Custom domains

The last item on the known-gaps list, and the biggest single piece of v0.4. A tenant
pointing `theirdomain.com` at their site touches routing, verification, and TLS — and
**TLS is a real fork that should be decided before any code is written**:

- **Cloudflare for SaaS** (custom hostnames API) — keeps Cloudflare in front as it is today,
  offloads cert issuance/renewal entirely, costs per hostname. Consistent with Cloudflare's
  current "dumb infra" role.
- **On-box ACME** (autocert, or Caddy in front on Coolify) — no per-hostname cost and no
  Cloudflare dependency, but the network process becomes responsible for issuance, renewal,
  and storing certs on the mounted volume.

Everything else follows from that choice:

- **Host mapping** — a `site_domains (domain PK, subdomain, verified, created)` table, and a
  `Dispatcher` lookup that falls back to it when the request host is *not* under `baseDomain`.
  This is the first time routing is not a pure string operation, so it needs the same LRU
  care the handler cache already gets.
- **Verification** — prove the tenant controls the domain (a TXT record, or a token served
  from a `.well-known` path) before serving it. Unverified domains must never route.
- **Tenant flow** — `friendo domain add theirdomain.com`, with the verification instructions
  printed in plain language, plus the equivalent in the console.
- **Coverage** — the dispatcher test gains custom-host cases; verification gets unit coverage.

## Open policy decisions (settle before, not during)

1. **Operator support-access into tenant sites.** Still open from the single-runtime pivot.
   The default power boundary is *site lifecycle + resources, not site content*; the
   alternative is "operator implicitly owns every site." If support-access lands it must be
   **explicit and audit-logged**, never implicit. This gates any "help a tenant fix their
   site" workflow.
2. **Storage quota accounting** — measured vs metered (see Tier A).
3. **Custom-domain TLS** — Cloudflare for SaaS vs on-box ACME (see Tier C).

## Housekeeping carried in

- **Confirm Resend on friendo.world.** Email delivery is now the *only* login path — an OTP
  that does not arrive is a total lockout, and this has not been re-verified since the
  cutover. Worth a synthetic check rather than a one-time manual confirmation.
- The `/activate` page open item in [network-accounts.md](network-accounts.md) was stale — it
  shipped ([accountauth.go](../runtime/go/network/accountauth.go)) and has been pruned.

## Coverage gaps this release should close

From the [ROADMAP.md](../ROADMAP.md) testing section, the two areas still untested are both
network-mode ones this release touches anyway:

- the live `friendo deploy` device-auth path against a running network;
- the storage backend against a real S3/R2 endpoint (today only the in-process test double).

## Explicitly not in v0.4

- **Phase 2 desktop editor** — the largest bet; independent track; form factor (desktop vs
  in-browser) still undecided.
- **`pull --community` snapshots** — carried forward from the v0.3 deferral list.
