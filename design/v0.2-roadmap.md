# friendo v0.2 — roadmap (draft)

Synthesized from a three-part codebase audit (runtime/content, CLI/deploy/platform,
quality/security) plus the recent auth/community work.

**Scope locked: Tier 0 + Tier 1 + Tier 2** (harden + full polish). The OTP-echo fix
is the top Tier-0 item, tackled as part of the sequenced blocker work.

### Execution sequence

1. ✅ **Tier 0 — Security**: OTP echo behind `FRIENDO_OTP_ECHO` + per-site email in
   provisioning; login + comment rate limiting (migration `0009`).
2. ✅ **Tier 0 — Correctness**: sync `authors` + `site_settings`.
3. ✅ **Tier 0 — Exposure**: export published-only + scrub the bundle DB.
4. ✅ **Tier 1 — Parity**: edge-engine fixes (nesting-aware for/if, `forloop.*`
   aligned to Pongo2, `'` escaping, filter aliases) verified by dual-boot render
   diff + a CI render smoke; canonical template spec in the docs; CORS removed +
   `Secure` cookie + push-timestamp parity; CI (`.github/workflows/test.yml`) runs
   both parity suites + a bundle-currency check on every PR.
5. **Tier 2 — Polish** (in progress): ✅ provisioning idempotency (orphan-clean
   create + teardown reporting); ✅ CLI polish (`friendo logout`, `export`
   re-imports `content/`, deploy first-push includes `--data`); ✅ **channels +
   messages** implemented as a **realtime** community feed (SSE — Go in-process
   hub, edge Durable Object; `<friendo-channel>` streams via EventSource; both
   runtimes verified live). Remaining: **locations** (geo-tagging) and
   **media/upload**.

Each step lands in both runtimes and extends the parity harness where it applies.

## North star

friendo's identity is *"your site is a folder — one UI, two runtimes, identical
behavior,"* aimed at **novice developers**, with an optional live multi-tenant
platform (friendo.world). So a credible **v0.2 tag** should mean:

1. **Safe to run publicly** — no anonymous visitor can impersonate a member, and
   the platform's public endpoints are rate-limited.
2. **Provably at parity** — the "identical behavior" invariant is *tested* for
   anything user data or templates flow through, not just the REST API.
3. **Coherent for a novice** — no silent data leaks, no "works locally, breaks on
   deploy," and the schema/feature surface tells an honest story.

Exhaustive test coverage, the desktop editor, custom domains, and bulk rollout are
explicitly **not** required for the tag.

## Tier 0 — Release blockers (must clear before a public 0.2 tag)

**Security (live-abusable today on friendo.world):**
- **OTP echo ships open on every provisioned site.** `handleRequestCode` returns
  the login `code` in the response whenever email is unconfigured, and the
  provisioner (`platform/worker.js` `deployUserWorker`) never sets
  `RESEND_API_KEY` — so anyone can request a code for any email, read it, and log
  in as that member. Fix: gate the echo behind an explicit dev flag (not "email
  happens to be unset"), **and** wire per-site email config into provisioning.
  Files: `runtime/go/api/api.go:~1244`, `runtime/edge/index.js:~410`,
  `platform/worker.js:100-106`. **Recommend fixing immediately, ahead of the rest.**
- **No rate limiting on login (or comment/vote).** Only `request-code` is
  limited. Add per-IP throttling to `/auth/login` and comment POST (reuse the
  existing `HasFreshOTP`/window pattern and `SSO_LIMITER`).

**Correctness — the features we just shipped don't survive a deploy:**
- **Sync `authors` + `site_settings`.** push/pull carry only `posts`+`users`, so
  deployed posts have dangling `author_id` (attribution blank; owner-scoped "my
  posts" inner-join silently drops them), and access policy (signups / approval /
  default-role) reverts to defaults on the live site — a security-relevant config
  drift. Both are config/identity, not visitor data, so they *should* travel.
  Files: `runtime/go/api/api.go` push/pull handlers, `runtime/edge/index.js`.

**Content-exposure (data leaks):**
- **Static export leaks drafts** — `export.go` uses `QueryCollection` (all
  statuses) instead of `QueryPublishedCollection`; drafts get baked into the
  public static site. One-line-class fix.
- **Bundle export tars the live DB** — `exportBundle` includes `data/friendo.db`
  with bcrypt hashes, live session tokens, and OTP rows. Exclude/scrub `data/`.

## Tier 1 — Parity integrity (make the headline invariant actually true)

- **Template-engine divergence** (the biggest silent Go↔edge gap): the edge
  regex engine mis-nests same-tag blocks (`{% for %}{% for %}…`), its filter set
  and loop-variable names differ from Pongo2 (`loop.index` vs `forloop.Counter`,
  `truncate` vs `truncatechars`), it's permissive on unknown filters while Pongo2
  hard-errors, and its `escapeHtml` omits `'` (an attribute-injection gap).
  → Publish **one canonical template-language spec** and drive both engines from
  it; add a **render-layer parity test** (nested loops, each filter, the loop
  counter) to the harness.
- **Parity nits:** align CORS (edge applies wildcard `cors()`, Go applies none),
  add `Secure` to session cookies, and align push timestamp defaults.
- **CI runs the tests on every PR** (today only the release workflow exists), and
  verifies the committed SPA/SDK bundles are current.

## Tier 2 — Coherence & polish (novice-facing)

- **Media / upload** — the most conspicuous missing "website builder" primitive.
  Decide: wire the `files` table into a real per-record upload API (+ image
  galleries / page bundles in the importer), or defer honestly.
- **`friendo export` re-imports `content/` first** (today it ships stale DB
  state); **deploy wizard's first push includes `--data`** (today a `content/`
  site deploys empty); add **`friendo logout`**.
- **Honest schema** — drop or implement the dead `channels`/`messages`/
  `locations`/`files` tables so "schema is the contract" holds.
- **Provisioning idempotency** — a failed `destroy` strands named D1/R2 and makes
  the subdomain permanently unclaimable; make teardown surface failures / adopt
  existing same-named resources.

## Deferred (post-0.2, documented)

Custom domains (Cloudflare for SaaS) · bulk runtime rollout + platform operator
role · Phase 2 desktop editor · per-member comment limits · persona switcher ·
server-side community template relations · SQL statement-splitter robustness ·
full render/CLI unit-test coverage · `pull --community` snapshots.

## Cross-cutting

The two highest-leverage guardrails, each closing a whole class of risk:
1. A **canonical template-language reference** both engines conform to (kills the
   render-divergence class).
2. **CI + expanded parity harness** (render + push/pull), so parity and data-flow
   are provably intact on every change.
